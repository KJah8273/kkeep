# Kkeep Roblox isolated runtime

Companion runtime for the existing Kkeep Roblox page. It preserves the provider's backend and browser-local per-user login while serving public launch assets with COOP `same-origin` and COEP `require-corp`. The dedicated origin prevents its service worker and game code from sharing Kkeep Profile storage.

The gateway forwards only public GET/HEAD asset requests. It does not forward visitor Authorization or identity cookies, does not provide a server account fallback, and discards provider diagnostic beacons. Login and authenticated Roblox requests use the existing provider WISP connection from the browser's session worker.

For the verified `version-f807b21caba84809` and `version-1ef59424f70d4932` engines, the loader uses 16384 memory pages (1 GiB) on iPad/mobile and changes the matching engine flag consistently. Both inspected binaries import shared memory with minimum 4096 pages and maximum 65536. Each compiled and linked with 16384 pages in Node using stub imports; the earlier version was also checked in Chrome. This verifies memory linking, **not gameplay, Safari support, or server joins**. Each profile names its exact loader variable and mobile predicate, which must still match before patching. Other engine builds are not assigned this override. Silent fallback to an arbitrary smaller heap is removed, and the duplicate response branch for the provider's engine cache is disabled on mobile.

`/check` resolves the current public engine metadata on each run, shows the upload version, and checks browser capabilities and engine compilation without an account. It performs the 1 GiB linking check only for an inspected profile. An unknown upload can compile but is not reported as a successful startup check. `/health` reports the gateway configuration. Neither endpoint collects user data. The app adds specific local startup messages for missing isolation, JSPI, memory, compilation, and linking.

Validation: `node --test tests/*.test.mjs`, `node scripts/build.mjs`, `node --check dist/server/index.js`. Preview: `sites-preview start <checkout>`.

This runtime is public and is active inside Kkeep's `/roblox` page.

The join flow applies performance preferences before the provider hook without reloading the selected game/server. The native WebTransport compatibility adapter supplies the legacy `datagrams.writable` getter using Safari's `createWritable()` when needed; it preserves native streams, packet contents, authentication, certificate verification, and transport backpressure. Provider game servers remain unchanged.

Revision `join4` sends join/launch and small metadata requests directly to the browser-local session worker over MessageChannel. This also covers engine workers whose fetches are not intercepted: their owned-worker channel forwards to the page, then its active session worker. The worker verifies the same-origin client path and target allowlist. Account requests and credentials never go to this public asset gateway. Requests are bounded, returned HTTP statuses are preserved, and a failed join is never automatically replayed. The worker registration is versioned and must answer a readiness handshake; existing login storage is retained.

The provider now supplies a WebTransport-over-WebSocket relay. Both hook copies (the page and embedded engine stub) use its existing `wss://api.spf50krem.com/_rbx/wt` endpoint, with its original target/path/certificate-hash parameters and frame protocol. Native connections retain the five-second fallback deadline. The fallback opens once, closes on cancellation, times out after fifteen seconds, and is also available when native WebTransport is absent. Native failure no longer displays a fatal overlay while the relay is still connecting. This repairs client routing, but does not guarantee that the provider relay or a particular Roblox server accepts a session.

`/_rbx/engine` is available as public metadata. Mobile sign-in and menu pages skip the provider's duplicate, fully buffered Wasm pre-download to avoid competing with the actual launch.

Connection checks record only fixed stage/error-name enums at `/_kkeep/connection`, never raw errors, server URLs, credentials, or game-session data. The last stage also appears locally under Loading help/startup check. A manual rejoin requests a fresh server connection without clearing login. A successful engine check still does not establish that Safari can join a live game server.

Sign-in startup and controller connection have deadlines. Safari may keep different browser storage for an embedded frame and a separate tab; the separate tab therefore continues through the full player flow rather than promising to transfer its sign-in back. The parent receives only `session-ready` or `session-failed` with a fixed reason enum, without credentials or arbitrary errors. `session-ready` means browser startup, not a successful account login or game join.
