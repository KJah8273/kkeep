# Adding games to Kkeep

New games should show only a cover and name in Games, open inside Kkeep, and use Profile progress sync by default (user preference, 2026-10-28).

For future uploaded game files, add the actual supplied game automatically with only its real cover and name. Do not add control overlays or outside-site branding. Use gameOnly for the player; sign-in stays available in the home Profile menu (user preference, 2026-10-29).

Register supported games in the save catalog and use SavedGamePlayer. Restore progress before startup and retain per-profile isolation, conflict detection, local fallback, and the previous cloud revision. For Unity games enable autoSyncPersistentDataPath and verify their IDBFS data round-trips through the save codec. Do not claim cross-device saving for external-only frames or server-owned progress without a working adapter.

Angry Birds Epic uses the supplied DarkTerraYT EpicWeb build through a local player shell. Its Unity IDBFS writes are captured by Kkeep's isolated save runtime. Binary assets and StreamingAssets remain on the source host and use the fixed-host resource relay; no upstream service worker is installed. Sign in to the same Kkeep Profile on each device before opening the game.

Among Us Old now loads a pinned local copy of its iPad player and decoded Unity build through SavedGamePlayer, retaining its joystick and touch keyboard. The game slug and IDBFS database stay unchanged, preserving Profile backups. The loader no longer depends on the external player or browser-side Brotli workers. The framework patch fixes a missing return in media API fallback, an undefined error variable after denied media enumeration, and non-finite spatial audio coordinates that Safari rejects. The iPad launch selects the build's supported WebGL 1 path, with antialiasing disabled; the compiled 512 MiB heap is retained. Startup errors remain visible with Retry and cannot be overwritten by late loading progress. Physical iPad gameplay remains unverified. Live multiplayer sessions and the external multiplayer server are not part of a progress backup. Existing saves on the standalone site's separate origin are not automatically imported.

The follow-up Among Us loader repair also bypasses the old identity-decompression Blob worker (which Unity created even for uncompressed files). Engine code registers through `framework.static.js`, loaded as a normal CORS script, instead of a generated Blob script inside the opaque save frame. Job callbacks remain asynchronous, bytes are not transferred/detached, and engine initialization exceptions report their original messages. Regression tests execute the actual legacy decompression function with Blob/Worker execution unavailable. This removes those startup dependencies; it does not establish successful physical iPad gameplay.
