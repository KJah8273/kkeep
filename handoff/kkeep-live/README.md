# kkeep

A responsive personal proxy browser with a tab bar, editable address bar, social and gaming shortcuts, and a Lite mode. It uses a locally bundled Scramjet browser rewriter and its own Cloudflare Worker HTTP/WebSocket relay. It does not depend on a public Wisp server or simply embed destination URLs.

## Development

Requires Node.js 24. Install the locked dependencies with `npm run install:ci`. Build with `npm run build`. Run the focused request-boundary and rewriter checks with `npm test`. Hosted configuration is in `.openai/hosting.json`; Sites owns the source repository and private deployment.

The user interface is `components/proxy-browser.tsx`; the app catalog is `lib/apps.ts`; the proxy integration is `public/engine/kha-runtime.js`; and the server relay is `worker/proxy.ts`.

## Behavior

- Roblox and Clash Royale have separate shortcuts and standalone players. `/roblox` and `?cloud=roblox` open Roblox; `/clash-royale` and `?cloud=clash` open Clash Royale. Each player has its own Server 1 and Server 2 choices.

- Each browsing tab has its own iframe and navigational history. Closing a tab disposes of its frame. A maximum of eight tabs bounds active page count.
- HTTP requests, form submissions, scripts, styles, images, and other fetches are routed through the relay. WebSocket connections use HTTP upgrades through the same Worker.
- Lite mode blocks requests identified by the proxy engine as images, audio, or video. It does not promise to block every media request generated by application JavaScript.
- A memory cache reuses small cacheable public assets. It expires entries, respects no-store/private/no-cache, skips requests with cookies or authorization, and uses at most 16 MiB. Reload clears this cache.
- Scramjet keeps destination-site cookies in its browser-local cookie jar, distinct from the hosting session. Hosting cookies and identity headers are never copied into upstream requests. No server-side browsing-history or password store is implemented.
- The relay accepts public HTTP(S)/WS(S) hostnames on standard ports. It blocks local/IP targets, validates public DNS answers, bounds uploads to 8 MiB, preserves redirects for rewriting instead of following them server-side, and rejects cross-origin entry into relay routes.

## Kkeep Party

The Party tab lists public rooms for every Kkeep visitor. Guest nicknames do not require an account or invitation. Rooms support two-player Tic-tac-toe and Connect Four, plus Galaxy Pairs for two to six players. A host starts each round and can start a rematch. Leaving hands hosting to the next player and returns the room to its lobby.

`worker/party.ts` keeps shared room state in D1, validates each move, hides unrevealed cards, and uses revision checks to avoid conflicting updates. Active games refresh about every 1.2 seconds, the room list every five seconds, and idle seats expire after 90 seconds. Rooms are public; seats in active/full games are unavailable until the round ends or a player leaves. An HTTP-only guest cookie permits rejoining from the same browser. Nicknames alone are device preferences; room/game state lives on the server.

Apply the generated `drizzle/0001_illegal_wallow.sql` migration through Sites publishing. Run `node --test tests/party.test.mjs` for multi-session discovery, complete rounds, capacity and move races, card visibility, expiry, and request validation checks.

## Proxy limitations

This is a web proxy, not a VPN or a replacement for native apps. It cannot change how other installed apps connect. Loading speed depends on the route, device, website, and connection; first-time proxy rewriting adds overhead. Some websites block server IPs or proxies. Logins, CAPTCHAs, calls, DRM, and cloud games may fail or require opening the original site. Clash Royale uses the separate Kkeep player and is subject to its cloud provider availability. Scramjet is experimental. No claim is made that every shortcut works end to end.

The build and deterministic relay tests are checked. The actual Scramjet WASM is exercised for HTML and JavaScript rewriting. Live egress in the authoring environment can be restricted; full browser interaction and account-login compatibility are not verified.
